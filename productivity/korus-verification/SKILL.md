> 구현을 맡길 때도, 사람이 수작업으로 검증할 때도 이 문서를 기준으로 합니다.
>
> **작성 근거**: 2026-10-06에 내려받은 실제 파일(`D:\dev\hermes\pr01\IN\`)을 읽기 전용으로 분석해,
> 아래 "검증됨"으로 표시한 내용은 추측이 아니라 실측값입니다. 개인정보는 이 문서에 옮기지 않았습니다.

## 2. 입력 파일 명세 (검증됨)

### 2-1. 엑셀 `교육훈련 결과관리_YYYYMMDDHHMMSS.xls`

- 형식: 실제 Excel 97-2003(.xls, OLE2). 시트 1개(`교육훈련 결과관리`), 헤더 1행.
- **마지막 행은 합계 행**(순번 칸이 `계`)이다. 데이터 행이 아니므로 반드시 제외한다. *(332행 중 331행이 데이터)*
- 맨 앞 열(헤더가 `1`)은 데이터가 아닌 보조 열이다. **열 위치가 아니라 헤더 이름으로 찾는다.**

판정에 쓰는 컬럼:

| 헤더 | 용도 | 비고 |
|---|---|---|
| `순번` | 행 식별자 (KORUS 화면 순번과 동일) | 리포트·결과 목록의 기준 키 |
| `과정명` | 증빙의 과정명과 대조 | |
| `실적시간` | 증빙 시간과 비교 | **두 칸**: 이 열=**시**, 바로 오른쪽 헤더 빈 열=**분** |
| `인정시간` | 증빙 시간과 비교 | **두 칸**: 이 열=**시**, 바로 오른쪽 헤더 빈 열=**분** |
| `교육훈련승인` | 판정 대상 선별 | 값: `대기중` / `승인` |
| `수료증빙파일` | 증빙 유무, 증빙 파일명 | 빈칸 = 증빙 없음 |
| `교번`, `성명` | 증빙의 성명과 대조 | |
| `교육기관명`, `교육시작일`, `교육종료일`, `학습방법`, `학습종류` | 참고 정보 (§5-3 선택 확장) | |

시간 칸: 숫자(실수)이며 시 0~21, 분 0~56 범위(10·20·25·30·32·35·36·40·41·50·56 등 **15분 단위가 아닌 값도 존재**).
→ 분 단위로 환산해(시×60+분) 비교한다.

### 2-2. 증빙 폴더 `증빙\`

- 하위 폴더 없음. 파일명 형식: **`{번호}_{원본파일명}`**
  예) `0_xxxx.pdf`, `100_xxxx_홍길동.pdf`
- **번호의 의미(검증됨)**: 엑셀에서 `수료증빙파일`이 있는 행만 **엑셀 순서대로 0, 1, 2 … 번째**로 센 값이다. 순번과 다르다.
- 한 행에 파일이 여러 개이면 **같은 번호**를 공유한다 (엑셀에는 `첫파일명.pdf 외 N건`으로 표기, 파일은 총 N+1개).
- 형식은 pdf가 대부분이고 xlsx·png·hwpx도 있다.

## 3. 증빙 매칭 규칙 (가장 중요)

이 프로젝트에서 가장 오래, 가장 크게 겪은 사고가 **"다른 행의 증빙과 비교"**였다. 같은 사고를 구조적으로 막기 위한 규칙이다.

| ID | 규칙 |
|---|---|
| **M1** | 엑셀의 **합계 행(`계`)은 제외**한다. |
| **M2** | `수료증빙파일`이 **빈칸이면 증빙 없음** → 판정하지 않고 "증빙없음(제외)"으로 기록한다. (**증빙이 있는 경우만 승인 여부를 판단**한다.) |
| **M3** | 증빙이 있는 행만 엑셀 순서대로 **0부터 번호 k**를 매긴다. 폴더에서 **`k_`로 시작하는 파일 전부**가 이 행의 증빙이다. |
| **M4** | **교차 확인(필수)**: `수료증빙파일` 값에서 ` 외 N건`을 뗀 이름(= 기준파일명)과 **끝이 정확히 일치**하는 파일이 번호 k 파일 중 **정확히 1개** 있어야 한다. 그리고 파일 수는 **1 + N개**여야 한다. 하나라도 어긋나면 그 행은 **"증빙 매칭 불가 → 수동 확인"**으로 두고 비교하지 않는다. |
| **M5** | **파일명만으로 찾지 않는다.** 같은 파일명이 여러 행에 있다 (실측: 5개 행이 이 경우). 번호(M3)가 1차 키, 파일명(M4)이 2차 확인이다. |
| **M6** | **엑셀은 정렬·필터·수정하지 않은 원본**을 쓴다. M3은 "내려받을 때의 엑셀 순서"에 의존하기 때문이다. 작업은 사본으로 한다. |

### 3-1. 시작 전 정합성 점검 (Preflight) — 통과해야 검증을 시작한다

| # | 점검 | 2026-10-06 파일 기준 기대값 |
|---|---|---|
| P1 | 증빙 있는 행 수 = 폴더 파일 번호의 고유 개수 | 157 = 157 |
| P2 | 번호가 0부터 빠짐없이 연속 | 0~156 |
| P3 | 폴더 전체 파일 수 = Σ(1 + N) | 161 = 157 + 4 |
| P4 | 증빙 있는 모든 행이 M4를 통과 | 157/157 |
| P5 | 엑셀 데이터 행 수 / 대기중 행 수 / 증빙없는 대기중 행 수를 출력 | 331 / 39 / 1 |

- **P1~P4 중 하나라도 실패하면 전체를 중단**하고 원인을 보고한다. (번호 규칙 자체가 깨졌다는 뜻이므로 일부만 진행하지 않는다.)
- 개별 행의 M4 실패는 전체 중단이 아니라 **그 행만 수동 확인**으로 넘긴다. 단, 실패 행이 전체의 일정 비율(예: 5%)을 넘으면 규칙이 깨진 것으로 보고 중단한다.

### 3-2. 여러 파일이 붙은 행 (`외 N건`)

- 실측: 3개 행이 해당 (추가 파일 4개). 추가 파일은 pdf·xlsx·hwpx 등이다 (참석자 명단, 통보 공문 붙임 등).
- **기본 처리(제안)**: 엑셀에 표기된 파일(기준파일)을 **본 증빙**으로 삼고, 나머지는 **보조 증빙**(주로 성명·명단 확인용)으로 함께 읽는다.
- 본 증빙에서 성명·과정명 등이 확인되지 않아 보조 증빙에 의존해야 하면 **확신도를 high로 두지 않는다.**
- ⚠ 이 처리는 **결정 필요 항목**(§10-1)이다.

### 3-3. 같은 증빙을 여러 행이 공유할 때

- 같은 원본 파일명이 여러 행에 있어도 **각 행은 번호(M3)로 각자의 파일**을 받는다 (내용이 같을 수도 다를 수도 있다).
- 같은 사람이 같은 파일명으로 두 행을 신청한 경우(실측 존재) **행마다 따로 판정**하고 리포트에 "동일 파일명 중복"을 표시한다.

## 4. 한 건 처리 절차

```
[행 선택] 대기중 행을 순번 순서대로 한 건씩
   │
   ├─ 증빙 없음(M2) ───────────────→ "증빙없음(제외)" 기록, 다음 행
   │
   ├─ 파일 찾기(M3) + 교차 확인(M4)
   │     └─ 실패 ─────────────────→ "수동 확인(증빙 매칭 불가)" 기록, 다음 행
   │
   ├─ 증빙 열기·텍스트 확보 (§4-1)
   │     └─ 실패 ─────────────────→ "수동 확인(증빙 판독 불가)" 기록, 다음 행
   │
   ├─ 엑셀 값 ↔ 증빙 값 대조 (§5)
   │
   └─ 판정·확신도·사유 기록 → 승인추천이면 "체크 대상 목록"에 순번 추가
```

### 4-1. 형식별 증빙 열기

| 형식 | 방법 | 비고 |
|---|---|---|
| PDF (텍스트 있음) | 텍스트 추출 | 추출 글자가 거의 없으면 스캔본으로 간주 |
| PDF (스캔본)·png·jpg | 이미지로 변환해 **vision 판독** | 성명 한두 글자 오인식 가능 → §5 성명 기준 |
| xlsx | 셀 텍스트 추출 | 보통 **명단**이다 → 해당 직원의 성명·교번이 명단에 있는지로 확인 |
| hwpx | 압축 내부 XML에서 텍스트 추출 | |
| 그 외·암호화·손상 | 판독 불가 → 수동 확인 | 조용히 건너뛰지 않는다 |

## 5. 판정 기준

기존 검증 기준(`verify()`)을 그대로 이어간다. 사용자가 확정한 원칙은 아래와 같다.

### 5-1. 6개 항목

| 항목 | 기준 |
|---|---|
| 성명 | 일치가 원칙. 스캔·사진 증빙에서 **자형이 비슷한 한두 글자 오인식**(예: 선↔신)은 일치로 본다. 완전히 다른 이름이면 불일치. |
| 기관 | 정확히 일치 (서울과학기술대학교) |
| 과정명 | 핵심 키워드(주제)가 같으면 일치. 기수·회차("제1기", "1차"), 특수문자, "스킬·과정·교육" 같은 부가어, 띄어쓰기 차이는 무시. 완전히 다른 주제만 불일치. |
| 시간 | **아래 5-2** |
| 문서 형식 | 이수증·수료증·참석확인증·교육이수증 등 공식 증빙이면 적합. 안내문·초청장·영수증은 부적합. |
| 발급 주체 | 기관명·직인·서명이 확인되면 적합 |

`승인추천` = 6개 항목 모두 적합일 때만 true.

### 5-2. 시간 규칙 (사용자 확정 — 반드시 지킨다)

1. 엑셀 시간 = `시 × 60 + 분` 으로 분 환산 (실적시간·인정시간 각각).
2. 증빙 시간도 분 환산 (`3시간`=180, `0.5시간`=30, `1일 8시간`=480, 일자별 표기는 합산).
3. **증빙 시간 ≥ 실적시간 이고 ≥ 인정시간 이면 일치.** 두 값 중 큰 쪽을 기준으로 비교한다.
4. **증빙 시간이 더 큰 것은 정상이다.** 확신도를 낮추지 않고, 사유에도 적지 않는다.
5. 증빙 시간이 더 **작을 때만** 불일치.
6. 엑셀 시간 칸이 비어 있어도 "미입력"이라고 단정하지 않는다. 증빙에 시간이 있으면 적합 처리하고 사유에 "엑셀 시간 확인 불가"만 적는다.
7. 증빙에 시간 표기 자체가 없으면 시간은 **판단 불가 → 수동 확인**.

### 5-3. 추가로 쓸 수 있는 정보 (선택 — 결정 필요 §10-2)

엑셀에는 기존 화면 판독으로는 못 얻던 값이 있다. 쓰면 검증이 더 단단해지지만 **기준이 바뀌는 것이므로 승인 후 적용**한다.

| 엑셀 컬럼 | 활용 | 기대 효과 |
|---|---|---|
| `교육시작일`·`교육종료일` | 증빙의 교육일자와 대조 | 엉뚱한 연도·다른 회차 증빙 적발 |
| `교육기관명` | 증빙 발급기관과 대조 | 기관 불일치 적발 |
| `학습방법` | 참석·집합교육은 명단형 증빙 허용 등 형식 기준 보정 | 문서 형식 오판 감소 |

### 5-4. 확신도

| 확신도 | 조건 |
|---|---|
| high | 6개 항목 모두 명확히 일치, 모호함 없음 |
| medium | 승인 추천이지만 성명 한두 글자 오인식, 과정명 부제목·기수 차이 등 일부 불확실 |
| low | 1개 이상 불일치, 또는 핵심 항목(성명·기관) 불확실 |

`CHECKBOX_THRESHOLD`(기본 medium)는 이제 **"체크 대상 목록에 올릴 최소 확신도"**로 의미가 바뀐다.

## 6. 출력물 및 실행 도구 (Reference Implementation)

모든 출력은 **별도 출력 폴더**에 만든다. 입력 엑셀·증빙 폴더는 읽기 전용으로 두고 절대 수정하지 않는다.

### 6-1. 표준 실행 스크립트
본 스킬의 일관된 수행을 위해 `scripts/` 폴더에 검증된 표준 파이썬 코드를 제공한다. AI는 이 코드를 우선적으로 사용하며, 환경에 맞게 경로만 설정하여 실행한다.

| 스크립트 | 역할 | 실행 명령 (예시) |
|---|---|---|
| `preflight.py` | 데이터 정합성 점검 (P1~P5) | `python preflight.py \"D:\\path\\to\\IN\"` |
| `verify_prepare.py` | 텍스트 추출 및 전처리 | `python verify_prepare.py \"D:\\path\\to\\IN\" \"D:\\path\\to\\OUT\"` |
| `verify_final.py` | 최종 대조 및 리포트 생성 | `python verify_final.py \"D:\\path\\to\\OUT\\evidence_data.json\" \"D:\\path\\to\\OUT\"` |

- 건별 카드: 순번·교번·성명·과정명, **KORUS(엑셀) 값 ↔ 증빙 값 나란히**, 항목별 일치 표시, 확신도, 사유
- 추가 표시: 사용한 **증빙 파일명**, 매칭 확인 결과(M4 통과), 다중 파일 행·동일 파일명 중복 경고
- 상단 요약: 아래 6-3 건수

### 6-2. 결과 엑셀 (.xlsx)

- 담당자가 순번으로 정렬·필터해서 KORUS 화면과 대조할 수 있게 한다.

### 6-3. 체크 대상 순번 목록 (담당자용)
- `승인추천 AND 확신도 ≥ 임계값` 인 행의 **순번만** 오름차순 나열 (예: `3, 5, 6, 9, …`).
- 담당자는 이 목록을 보며 KORUS 화면에서 체크하고, **「교육훈련승인일괄반영」은 담당자가 직접** 누른다.

### 6-4. 요약과 건수 정합성
```
대기중 N건 = 승인추천 a + 검토필요 b + 증빙없음(제외) c + 수동확인 d
```
- **합이 N과 다르면 오류**로 보고 리포트 맨 위에 경고한다. 행이 조용히 사라지는 것이 이 작업에서 가장 위험한 실패다.
- 수동 확인 건은 사유별로 분류한다: 증빙 매칭 불가 / 증빙 판독 불가 / 시간 판단 불가.

---

## 7. 절대 규칙 (불변)

1. KORUS에 접속하거나 화면을 조작하지 않는다. **저장·일괄반영 버튼은 어떤 경우에도 자동으로 누르지 않는다.**
2. **증빙이 있는 경우만 승인 여부를 판단한다.** 증빙이 없거나 매칭이 불확실하면 판단하지 않고 수동 확인으로 남긴다.
3. 증빙 시간이 실적·인정시간보다 크면 문제없다 (§5-2).
4. **불확실하면 "승인 추천"으로 올리지 말고 수동 확인으로 보낸다.** 틀린 승인 추천이 놓친 추천보다 비용이 크다.
5. 어떤 행도 조용히 누락하지 않는다 (§6-4 정합성).
6. 입력 파일은 읽기 전용. 결과는 별도 폴더에만 쓴다.
7. **개인정보 보호**: 엑셀·증빙·리포트에는 직원 실명·교번이 있다.
   - 판독·대조는 **온프레미스 모델만** 사용하고 외부 서비스로 보내지 않는다.
   - 로그·콘솔에는 순번 위주로 남기고 개인정보 출력을 최소화한다.
   - 결과물 공유 시 개인정보 포함 사실을 알린다.
8. API 키는 설정 파일에서만 입력받고 코드·문서에 넣지 않는다.

## 8. 예외 상황 처리표

| 상황 | 처리 |
|---|---|
| 합계 행(`계`) | 제외 (M1) |
| `교육훈련승인`이 `승인` | 판정하지 않음 (참고·정확도 점검용으로만 사용 가능, §9) |
| `수료증빙파일` 빈칸 | 증빙없음(제외) |
| 번호 k 파일 없음 / 기준파일명 불일치 | 수동 확인(증빙 매칭 불가), 비교하지 않음 |
| 번호 k 파일 수가 `1+N`과 다름 | 수동 확인(증빙 매칭 불가) |
| 같은 파일명이 여러 행에 존재 | 번호로 구분, 리포트에 중복 경고 |
| 한 행에 파일 여러 개 | §3-2 |
| 스캔 PDF·이미지 | vision 판독, 성명 오인식 허용 기준 적용 |
| 명단형 증빙(xlsx, 참석자 명단) | 해당 직원 성명·교번이 명단에 있는지로 성명 확인, 시간·과정명은 본문·제목에서 확인 |
| 한 증빙에 여러 사람 | 해당 직원 부분만 대조 |
| 증빙에 시간 표기 없음 | 시간 판단 불가 → 수동 확인 |
| 암호화·손상·미지원 형식 | 수동 확인(증빙 판독 불가) |
| 엑셀 시간 칸 비어 있음 | §5-2의 6번 |
| AI 서버 오류·타임아웃 | 1회 재시도 후 실패하면 수동 확인(사유 기록), 전체 중단하지 않음 |

## 11. 한계와 주의

- **번호 규칙은 관찰된 동작이다.** 증빙 일괄 내려받기 도구가 "증빙 있는 행 순서대로 번호를 붙인다"는 공식 사양은 확인하지 못했고, 이번 파일에서 157/157로 일치한 것을 근거로 한다. 그래서 **매번 Preflight(§3-1)로 다시 확인**한다. 내려받기 도구가 바뀌면 규칙이 달라질 수 있다.
- **엑셀은 내려받은 시점의 스냅샷이다.** 그 사이 KORUS에서 승인 상태가 바뀌었을 수 있으므로, 체크하기 전에 화면의 순번·승인 상태를 한 번 대조한다.
- **엑셀의 시간 값이 화면 표시와 같은지** 첫 실행 때 표본 몇 건을 화면과 직접 대조해 확인한다.
- **체크박스 자동 선택이 없어진다.** 대신 순번 목록의 정확성에 집중한다.

### 구현 시 유의 (참고 관찰)
- `.xls`는 이 PC의 Python 환경에서 바로 읽히지 않는다 (`pandas`는 `numpy` 부재로 실패, `xlrd` 미설치). 구현 방식은 ① `xlrd` 설치 ② 엑셀에서 `.xlsx`로 저장 후 `openpyxl` ③ 설치된 Excel COM 중 선택해야 한다.
- 헤더에 줄바꿈이 있는 이름(`지정학습\n여부`)과 **빈 헤더 칸(시·분의 분 칸)**이 있으므로, 컬럼은 이름 + "바로 오른쪽 칸" 규칙으로 찾는다.
